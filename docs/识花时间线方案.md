# 识花时间线方案（首页最近收获升级）

> 状态：已实施（2026-08-16 设计定稿并实施完成，详见 [修复与优化记录](修复与优化记录.md)）
> 关联文档：[技术文档](技术文档.md)｜[需求方案](需求方案.md)｜[SCHEMA.md](SCHEMA.md)｜[修复与优化记录](修复与优化记录.md)

## 一、目标

将首页（识花页）的「最近收获」区域升级为**可滑动的识花时间线**：

1. 时间轴放在左侧，按**小时**划分节点（每个识别发生的小时一个节点）记录在时间轴上；
2. 时间节点可**左右滑动**切换，查看当前时间节点（该小时）收录了哪些花；
3. 每个节点内展示该小时收录的花及**对应的拍摄照片**（可预览大图），并标注每条记录的**具体时间（精确到分钟）**。

## 二、现状盘点

### 2.1 现有「最近收获」

- 首页 `index.wxml`：`scroll-view scroll-x` + `flower-card` 横向卡片流（仅 6 张，`compact` 模式）；
- 数据来源：`getAchievements.recentCards`（每项仅含 `_id/cnName/latinName/rarity/illustrationFileID/aiGenerated/meetCount/lastMetAt`，**不含照片**）；
- 交互：点击卡片跳详情页；无时间概念。

### 2.2 时间线数据基础（关键）

`user_cards.photos` 数组的每条记录就是一次识别入库事件：

```
photos: [{ fileID, addedAt, location?, note? }, ...]
```

- `saveCard` 的 `create`（首次收录）与 `addPhoto`（重复遇见）都会向 `photos` push 一条记录，`addedAt = Date.now()`；
- `meetCount` = 识别入库次数（含首次），与 photos 长度一致（正常情况下）；
- **每张照片的 `addedAt` 即该次识别的时刻**，天然构成时间线节点；
- **边界**：单卡照片上限 `MAX_PHOTOS = 30`（`saveCard`），即单卡时间线最多 30 个节点，超限后 `PHOTO_LIMIT` 拒绝新增——时间线完整度受此限制（当前可接受，见风险节）。

### 2.3 可复用资产

- 照片全屏预览：`detail.js` 的 `wx.previewImage`（支持 cloud:// fileID）模式可复用；
- 时间格式化：`util.formatDate`（yyyy-MM-dd）已有，时间线需补充「今天/昨天/时分」粒度；
- 花卡信息：`flower-card` 组件 + `getCollection` 的花种字段合并模式。

## 三、交互设计

### 3.1 布局

首页「最近收获」区替换为「识花时间线」卡片：

```
┌─────────────────────────────────────┐
│  识花时间线                          │
│  ┌─────┬─────────────────────────┐  │
│  │ 时间轴 │  节点内容（左右滑动）        │  │
│  │  │●    │                        │  │
│  │  │●    │   [14:32 花卡+照片]      │  │
│  │  │●    │   [14:05 花卡+照片]      │  │
│  │  │●    │                        │  │
│  └─────┴─────────────────────────┘  │
└─────────────────────────────────────┘
```

- **左侧时间轴**（固定宽约 120rpx）：竖向线段 + 圆点 + 时间标签（按小时，如「今天 14:00」「昨天 11:00」「8-15 09:00」）；
- **右侧节点内容**（`swiper` 横向滑动）：每个 slide 对应一个时间节点，展示该节点收录的所有花；
- 节点与 slide 一一对应，滑动/点击时间轴节点均同步切换。

### 3.2 时间节点定义

- **节点 = 一个小时间隔**：把该小时内的所有识别入库记录（`create` 与 `addPhoto`）聚合为同一节点；
- 同一小时内有多次识别（可能同花多次、也可能不同花）→ 同一节点内多条记录；
- 节点按小时**倒序**排列（最新在前，与「最近收获」语义一致），同一小时内记录按 `addedAt` 升序；
- 时间轴标签：今天（「今天 HH:mm」）、昨天（「昨天 HH:mm」）、更早（「MM-DD HH:mm」/「YYYY-MM-DD HH:mm」）；
- **节点内每条记录标注精确到分钟的时间**（如「14:32」，同小时内可区分先后）。

### 3.3 节点内容

每个节点 slide 展示该小时内收录的**全部记录**（按时间升序），每条记录：

1. **记录头**：**精确到分钟的时间**（如「14:32」）+ 花种中文名 + 稀有度 + 「第 N 次遇见」（该记录在对应花卡中的 meetCount 序号）；
2. **照片**：该次识别的实拍照片（`fileID`），点击 `wx.previewImage` 全屏预览；
3. **花卡信息**：复用 `flower-card` 或轻量卡片（插画 + 花名），点击跳详情页；
4. 可选：照片 `location`（有则显示，如「公园东门」）。

> 同一小时内多次识别同一种花 → 显示多条记录（各带各自分钟时间）；同一小时不同花 → 依次列出。

### 3.4 空态与降级

- 无任何记录：沿用现有空态（「还没有收集记录，快去拍第一朵花吧」+ 去识花按钮）；
- 单节点多花：同一时刻（同一照片记录只会对应一种花，因此一个节点一般一种花；若未来支持多花合并再扩展）；
- 照片缺失（fileID 失效）：显示插画占位，不阻断时间轴。

## 四、数据与接口设计

### 4.1 数据来源

时间线节点**不落库、实时聚合**（沿用项目「实时推导」原则）：由 `user_cards.photos` 直接推导。

### 4.2 getAchievements 返回扩展

在现有 `getAchievements` 返回中新增 `timeline` 字段（首页单请求不变，避免新增云函数）：

```
timeline: [{
  hourTime: number,     // 节点锚点：该小时第一条记录的 addedAt（或整点时间戳）
  hourLabel: string,    // 前端拼：今天/昨天/MM-DD + HH:00（时间轴标签）
  records: [{           // 该小时内收录的全部记录（按 addedAt 升序）
    time: number,       // 该次识别时间戳（照片 addedAt）
    minuteLabel: string,// 前端拼：精确到分钟 HH:mm（记录内标注）
    meetIndex: number,  // 该记录在对应花卡中的第几次遇见（1-based）
    species: {          // 该次识别的花（复用 recentCards 单卡结构）
      _id, cnName, latinName, rarity, illustrationFileID, aiGenerated
    },
    photo: { fileID, location, note }  // 该次识别的照片
  }]
}]
```

- 聚合逻辑：遍历当前用户全部 `user_cards` → 把每张 `photos[i]` 展开为一条原始记录 → 按「整点小时」分组（`new Date(addedAt)` 的 Y/M/D/H 相同为一组）→ 组内按 `addedAt` 升序 → 组间按小时**倒序** → 取前 N 组（默认 30 组，可配置 `TIMELINE_LIMIT`）；
- `meetIndex`：photos 数组下标 +1（photos 顺序即遇见的先后，`_.push` 追加保证有序）；
- `hourLabel` 用组内第一条记录的整点（如 14:00）；`minuteLabel` 用每条记录的 HH:mm；
- 原 `recentCards` 保留（兼容），或由前端改为用 `timeline` 前 6 条记录推导（推荐后者，减少冗余）。

### 4.3 花种信息合并

`getAchievements` 已加载 `speciesList` + `cardBySpecies`，按 `speciesId` 直接取花种字段，无需额外查询。

## 六、边界与风险

| 风险 | 对策 |
|---|---|
| 单卡照片上限 30（`MAX_PHOTOS`）→ 时间线最多 30 节点/卡 | 时间线按照片记录聚合，天然受此上限约束；30 节点已满足「最近」浏览需求；后续如需完整历史可独立建识别事件表（本次不做） |
| 照片被删除（`deletePhoto`）→ 时间线节点消失 | 与数据语义一致（照片即事件）；删除后该节点不再显示，`meetCount` 不减（现有行为） |
| 花种被禁用/删除 → 节点花种信息缺失 | 节点保留照片，花种字段置空/占位，不崩溃 |
| timeline 数据量（30 小时组 × 组内若干记录） | 远小于现有全量下发，性能无忧；`TIMELINE_LIMIT` 按组数截断 |
| 时间标签跨年 | `formatTimelineTime` 处理跨年显示完整日期 |
