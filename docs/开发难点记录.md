### 1. 原有技术实现

- 选图：`util.chooseOneImage` 用 `wx.chooseMedia` `count: 1`，一次只能选 **1 张**；
- 识别：单图 `phase: idle → recognizing → result → success`，`candidates` 为单张图的 Top3 候选、`selectedIndex` 单选、`confirmSave` 只入库一张；
- 识别链路上限：每日 **20 次**（`RECOGNIZE_DAILY_LIMIT` 云函数事务强制）、云函数 **20s 超时**、单张约 3~5s、图片最长边 ≤1080 质量 75、MD5 同图去重不扣次数；
- 未收录花生成：单图触发「收录并生成花卡」→ `requestFlowerGenerate` 建任务 → `pollGenTask` 轮询（4s×45 次≈3 分钟）→ `attachSpecies` 挂花种；`genIndex` 保证同一时间只 1 个生成任务；worker **每 2 分钟只处理 1 个**任务、每日生成上限 **3 次**。

### 2. 当前要实现的功能

从相册**多选**（单次 ≤5 张）一次性识别多张：逐张串行识别 → 批量统一清单确认；失败单张跳过标记、最后统一处理；中途退出保留已识别结果；并兼容**未收录花（新物种）**的批量生成与收录。

### 3. 实现方案与原因

**核心约束推导（决定方案形态）**：

1. **必须逐张串行**：`recognizeFlower` 云函数超时 20s，单张约 3~5s，一次调用处理多张必超时——所以批量 = 前端逐张循环调 `recognizeFlower`，每张独立上传/识别，进度「3/5」；
2. **选图按剩余次数截断**：批量 N 张消耗 N 次每日配额，选图时 `min(选中数, 剩余次数)`，超出提示并截断；
3. **统一清单确认（方案 B）**：多张结果集中在 `batch_result` 阶段逐张确认，每张默认第一个命中候选、可展开切换 Top3 / 手动纠正；「确认全部入库」逐张 `saveCard(create)` 汇总；
4. **新物种批量生成的关键取舍**：
   - worker 每 2 分钟只处理 1 个任务 → 多张未收录花必须**串行排队**，且**生成完成前该张不可确认入库**（无 species 无法入库）；
   - 每日生成上限 3 次 → 生成前**前置配额提示**（`GEN_LIMITED` 兜底）；
   - 队列长耗时 → 明确提示「按序生成，完成后图鉴可查」，中途退出后台继续（worker 处理，任务不丢）；
5. **数据模型**：单图 `candidates` 扩展为多图 `batchList`（每项含 `tempPath/fileID/status/candidates/selectedIndex/confirmed/genState/speciesId`），新增 `phase: 'batch'`（识别中）与 `'batch_result'`（清单确认），单图路径保留兼容。

**详细设计见** [批量识别方案](批量识别方案.md)。

### 4. 实施反馈与结论（结果）

- **实施结果（2026-08-16）**：已落地——`util.chooseMultiImages` 多选、`runBatchRecognize` 逐张串行、`batch_result` 清单确认（展开切换候选/失败重试/存相册/确认全部入库汇总）、批量未收录花生成（串行锁 + `GEN_LIMITED` 配额提示 + 生成中置灰）、首页相册入口改多选；单图路径保留兼容（`onLoad` 按 tempPath/tempPaths 分发）；
- **验证**：`node --check` 通过；批量核心逻辑测试 10 项 `ALL PASS`（初始化占位、成功/失败/重复/未收录各态、确认过滤、汇总计数）；
- **待真机验证**：批量耗时（5 张约 15~25s）、生成排队体验、中途退出保留已识别、单图路径回归；
- **遗留待复盘**：批量中 MD5 重复图自动跳过（不弹窗）的交互细节、生成中张与「确认全部入库」的并发边界、失败张「换一张重试」当前复用单图识别流程的体验。
