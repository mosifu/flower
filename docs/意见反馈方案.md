# 意见反馈功能方案（我的页 · 用户反馈收集）

> 状态：已实施（2026-08-16 设计定稿并实施完成，详见 [修复与优化记录](修复与优化记录.md)）
> 关联文档：[技术文档](技术文档.md)｜[需求方案](需求方案.md)｜[SCHEMA.md](SCHEMA.md)｜[修复与优化记录](修复与优化记录.md)

## 一、目标

在「我的」页新增**意见反馈**入口（位于「关于」与「注销账号」之间），收集用户使用体验与 Bug 反馈；
用户可查看自己的历史反馈；开发者通过**云开发控制台**查看全部反馈记录。

## 二、决策记录（已与用户确认）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 入口位置 | 新建「支持」区块，插在「关于」与「账号」之间 | 用户指定 A 方案 |
| 反馈形态 | 结构化表单：类型 + 文字 + 可选截图 | 用户指定 C 方案，便于分类处理 |
| 联系方式 | 不收集 | 用户指定 A 方案，个人主体小程序拿手机号受限 |
| 查看渠道 | 云开发控制台看 `feedback` 集合 | 用户指定 A 方案，零后台开发；后续可加管理员页增强 |
| 历史可见 | 用户可见自己的历史反馈 | 用户确认 |
| 注销处理 | 注销后用户不可见旧反馈，但记录保存在案（openid 匿名化） | 用户确认，数据保留供开发者留档 |
| 反垃圾 | 每用户每日最多 5 条 | 用户指定，仿 gen_limits 先例 |
| 截图上限 | 3 张 | 用户确认，成本/体积控制 |
| 历史反馈处理状态 | 不显示处理状态（无后台标记） | 用户确认，仅展示提交时间 |

## 三、数据模型（2 个新集合）

### 3.1 feedback（反馈主表，仅管理端可读写）

```
_id: string            # 自动生成
openid: string        # 提交者 openid（注销时置空匿名化，记录保留）
type: string          # suggestion 体验建议 | bug 问题反馈 | other 其他
content: string       # 反馈内容（≤500 字）
photos: []            # 截图 fileID 数组（可选，≤3 张）
createdAt: number     # 提交时间
```

### 3.2 feedback_limits（每日条数限流，仿 gen_limits）

```
_id: "{openid}_{yyyyMMdd}"
openid: string
date: string          # yyyyMMdd
count: number         # 当日已提交条数（上限 5）
```

## 四、云函数（2 个）

### 4.1 submitFeedback — 提交反馈

**入参**：`{ type, content, photoFileIDs? }`

**流程**：
1. 校验：`type` 白名单（suggestion/bug/other）、`content` 非空且 ≤500 字、`photoFileIDs` ≤3 张；
2. 每日限流：`feedback_limits` 事务校验（count < 5），超限返回 `FEEDBACK_LIMITED`；
   （反馈无外部成本，写入成功后才计数，避免用户因失败被扣次数）
3. 截图内容安全：下载逐张 `imgSecCheck`（违规拒绝并清理文件，复刻 saveCard 先例）；
4. 入库 `feedback.add()` → 返回 `{ ok, feedbackId }`。

### 4.2 getMyFeedback — 我的历史反馈

**入参**：`{ page? }`（默认第 1 页，每页 10 条）

**返回**：`{ ok, list[], hasMore, page }`
- 按 openid 查询，`createdAt` 倒序；只返回自己的反馈（注销后 openid 置空，自然查不到旧记录）。

## 五、前端交互

### 5.1 入口（profile.wxml）

在「关于」区块后、「账号」区块前新增：

```
<view class="section-title">支持</view>
<view class="card about-card">
  <view class="about-line" bindtap="goFeedback">💬 意见反馈</view>
</view>
```

### 5.2 反馈页 pages/feedback/（4 文件，navigateTo 进入）

上下两区：

1. **提交表单**（顶部卡片）：
   - 类型：三个胶囊单选（😊 体验建议 / 🐞 问题反馈 / 💡 其他）；
   - 内容：textarea（≤500 字，实时字数计数）；
   - 截图：`wx.chooseMedia` 选图（≤3 张）→ 压缩上传（复用 `util.uploadImage`）→ 缩略图预览 + 可删除；
   - 提交：成功后清空表单、toast、刷新下方历史。
2. **我的反馈**（下方列表）：倒序展示 类型标签 + 时间 + 内容 + 截图缩略图（点击 `wx.previewImage` 预览），`onReachBottom` 分页加载。

## 六、注销处理

`deleteAccount` 中追加：将该用户 `feedback` 的 `openid` 匿名化置空（批量更新）。

- 记录保留在案（开发者仍可在控制台查看全部反馈）；
- 用户注销后重进（同一微信号 openid 不变），`getMyFeedback` 按 openid 查不到 → 不可见旧反馈。

## 七、开发者查看反馈（渠道 A）

- 云开发控制台 → 数据库 → `feedback` 集合，按 `createdAt` 倒序查看；
- 截图云存储前缀 `feedback-photos/`（按 openid 子目录隔离）；
- 后续增强：`ADMIN_OPENIDS` 白名单管理员页（项目已有 initSpecies 先例），列为 Roadmap。

## 八、合规与文档

- 隐私政策补一条：反馈内容（含截图）仅用于产品改进、开发者可见；
- 截图必须过内容安全检测（项目既有规范）；
- 文档同步：`SCHEMA.md`（新集合）、`技术文档.md`（云函数）、`需求方案.md`（F-07 我的页）、`README.md`、`修复与优化记录.md`（实施批次）。
