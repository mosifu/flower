## 一、项目概述

「随心一拍-花知道」是一个基于 **微信小程序原生框架 + 微信云开发（CloudBase）+ 百度 AI 植物识别** 的识花收集类小程序。核心闭环：

> 拍照/选图 → AI 识别（Top3 候选）→ 用户确认/手动纠正 → 生成水彩花卡入库 → 图鉴收集 → 等级与成就激励

| 维度 | 说明 |
|---|---|
| 前端 | 微信小程序原生（JS + WXML + WXSS），无第三方框架 |
| 后端 | 微信云开发：云函数（Node.js）+ 云数据库 + 云存储 |
| 外部服务 | 百度智能云「植物识别」API（图片识别） |
| 开源协议 | Apache License 2.0 |

### 2.1 技术要点

- **无自建服务器**：全部后端能力由云开发提供，无需域名备案服务器（小程序本身仍需 ICP 备案）。
- **身份体系**：不维护用户表，身份一律取自 `cloud.getWXContext().OPENID`，前端禁止传 openid。
- **实时推导型数据**：等级、徽章、收集率等**不落库**，每次由 `getAchievements` 根据 `user_cards` 实时计算——删除卡片自动回退，杜绝数据不一致。
- **密钥安全**：百度 AK/SK 仅存云函数环境变量，Token 缓存于云数据库 `bd_token`。

## 四、数据库设计

4 个集合，详细字段见 [SCHEMA.md](SCHEMA.md)，此处补充设计要点。

### 4.1 species — 花卉知识库（60 条，只读为主）

- `_id` 即花种 id（拼音小写），保证导入幂等。
- `rarity` 四档：common(28) / rare(19) / epic(11) / legendary(2)。
- `synonyms` 别名数组用于百度识别结果匹配。
- `illustrationFileID` 为水彩插画的云存储 fileID（或 https URL），空则前端显示占位符。

### 4.2 user_cards — 用户花卡

- 同一 `openid + speciesId` 唯一对应一张卡（**业务唯一键**，无数据库层约束，由代码保证）。
- `photos` 为照片数组，每张含 `{ fileID, addedAt, location?, note? }`。
- `meetCount` 为「第 N 次遇见」（实际语义为识别入库次数）。
- 删除卡/照片**只删数据库记录**，云存储文件不自动清理（已知限制，见评审文档）。

### 4.3 rate_limits — 每日限流计数

- `_id = "{openid}_{yyyyMMdd}"`，`count` 用 `_.inc(1)` 原子自增。
- **无过期机制**，数据永久累积（建议定期清理，见评审文档）。

### 4.4 bd_token — 百度 Token 缓存

- 固定 `_id = "baidu"`，`expireAt` 提前 60s 失效，避免边界过期。
- 并发刷新风暴风险（多个请求同时发现过期同时刷新），见评审文档。

## 五、云函数接口文档

统一返回约定：`{ ok: true, ... }` 或 `{ ok: false, code, message }`。
前端 `utils/util.js:callFunction` 将 `ok=false` 转为抛错，`err.code` 供按需处理。

### 5.1 recognizeFlower — 识花主链路

**职责**：每日限流 → 微信图片内容安全检测 → 百度植物识别 → 知识库匹配。

**入参**：`{ fileID, force? }`（fileID 为云存储文件 ID；`force: true` 跳过图片指纹查重，用于用户确认「仍要识别」重复图片）

**返回**（正常）：
```json
{
  "ok": true,
  "hit": true,                  // 是否有候选命中知识库
  "candidates": [               // Top 3 候选
    {
      "name": "月季", "score": 0.982, "scoreText": "98.2%",
      "baike": { "description": "..." } | null,   // 百度百科信息
      "species": { "_id": "yueji", "cnName": "...", "rarity": "...", ... } | null
    }
  ],
  "remaining": 19, "limit": 20
}
```

**返回**（MD5 指纹命中重复，不消耗限流次数）：
```json
{
  "ok": true,
  "duplicate": true,
  "hit": { "speciesId": "yueji", "cnName": "月季", "createdAt": 1723000000000 }
}
```

**错误码**：

| code | 场景 |
|---|---|
| `NO_OPENID` | 无法获取用户身份 |
| `NO_FILE` | 缺少图片参数 |
| `RATE_LIMITED` | 今日识别次数已达上限 |
| `DOWNLOAD_FAIL` / `EMPTY_FILE` | 图片下载失败 / 内容为空（服务端原因，退次数） |
| `UNSAFE_CONTENT` | 图片内容不合规（用户过错，不退次数） |
| `BAIDU_CONFIG` | 未配置 BAIDU_AK/SK（退次数） |
| `BAIDU_TOKEN_ERROR` | 百度 Token 获取失败（退次数） |
| `BAIDU_ERROR` | 百度识别接口报错（退次数） |
| `SEC_CHECK_ERROR` | 严格模式下安全检测不可用（退次数） |

**执行流程**：

1. **下载图片**：`cloud.downloadFile`（提前下载以计算 MD5 指纹）。
2. **图片指纹查重**（`findDuplicate`，`force !== true` 时）：计算图片 buffer 的 **MD5**（前端固定参数压缩 → 同图字节一致）→ 查 `photo_hashes`（按 openid 隔离）。命中返回 `{ ok: true, duplicate: true, hit }`，**不消耗限流次数**；`force: true` 跳过（用户确认仍要识别）。
3. **限流**（`consumeRateLimit`）：**数据库事务**（读计数 → 校验 → `set` 自增），并发下不会超限；超限拒绝不扣费。
4. **内容安全**（`checkImageSecurity`）：`imgSecCheck`，jpeg 失败自动换 png 重试；`errCode 87014` 判不合规。接口异常时**默认放行**（fail-open），`SEC_CHECK_STRICT=true` 时拒绝（fail-closed）。
5. **百度识别**：`getBaiduToken` 取缓存 token（`bd_token`），过期则走 OAuth 刷新（**模块级 Promise 锁防并发刷新**）；POST `image-classify/v1/plant`，`baike_num=3`，body 为 base64 表单。
6. **知识库匹配**（`matchSpecies`）：名称规范化（去空格、小写、去括号）后与 `cnName / latinName / synonyms` **全等匹配**；命中才挂 `species` 信息。
7. **写入指纹**（`savePhotoHash`）：识别成功（百度正常返回）后写入 `photo_hashes`（幂等 `_id = openid_md5`，记录命中花种 id），未命中也写（空 speciesId）——防止同一张图反复消耗次数。

**健壮性设计**（2026-08 优化批次）：

- **失败退款**：下载失败/百度错误/安全接口异常/内部错误等**服务端原因**自动退还当日次数（`refundRateLimit`，计数 >0 才退）；内容不合规属用户过错不退。
- **失败清理**：识别链路任何失败都会删除已上传的 `fileID`，避免孤儿文件。
- **知识库缓存**：species 列表 10 分钟实例内存缓存（查询失败回退旧缓存 1 分钟）。
- **MD5 永久去重**：重复图片在限流前拦截（不消耗次数）；指纹随 `deleteAccount` 删除、`cleanupData` 90 天清理。局限：仅精确字节级（同图重传），同一朵花新拍照片不命中（近似去重 dHash 留待 Roadmap）。

### 5.2 saveCard — 花卡入库与维护

**入参**：`{ action, speciesId, photoFileID?, location?, note?, photoIndex? }`

| action | 说明 | 额外入参 |
|---|---|---|
| `create` | 确认入库；已收集则追加照片并 `meetCount+1`；**内容安全检测** | `photoFileID` 必填 |
| `addPhoto` | 已收集卡追加照片；**内容安全检测**；单卡照片 ≤30 | `photoFileID` 必填 |
| `updateNote` | 更新卡片级备注（≤200 字） | `note` |
| `updateLocation` | 更新卡片级地点（≤100 字，详情页有 UI） | `location` |
| `deletePhoto` | 按 `photoIndex` 删除单张照片（数组整体覆写），**同步清理云存储原图** | `photoIndex` |
| `deleteCard` | 删除整卡（图鉴/成就由读取端实时重算），**同步清理全部云存储照片** | — |

**校验**：除 `deleteCard` 外均先校验 `speciesId` 存在且 `enabled !== false`；所有操作按 `openid + speciesId` 查询归属，保证只能操作自己的卡片；服务端校验 note/location 长度、photoFileID 类型、photoIndex 整数，超限返回 `BAD_PARAM`；照片超上限返回 `PHOTO_LIMIT`。

**新增错误码**：`BAD_PARAM`（参数不合法）、`PHOTO_LIMIT`（照片数超限）、`UNSAFE_CONTENT`（内容不合规，已清理文件）、`DOWNLOAD_FAIL`（文件读取失败）。

### 5.3 getCollection — 图鉴数据

**入参**：`{ speciesId?, season?, status?, sortBy? }`（均可选，不传返回全量）

- `speciesId`：详情页单查
- `season`：花期筛选
- `status`：`all` / `collected` / `uncollected`（服务端过滤）
- `sortBy`：`default` / `letter` / `season` / `latest`

**返回**：`{ ok, list[], stats { total, collected, rate } }`

- `list` 为 species 与用户收集状态合并后的数组（含 `collected / meetCount / photos / note / firstMetAt` 等）。
- **排序规则**（2026-08-11 图鉴排序需求，已收集优先规则后续调整）：
  - 全部页签（`status=all`）**仅「默认」排序**时**已收集优先分组**；主动选择 `letter`/`season`/`rarity`/`latest` 时**全体混排**（用户后续调整）
  - 已收集页签默认（`sortBy=default`）：按**最近遇见时间倒序**
  - `letter`：中文名拼音升序（`localeCompare zh`，云函数 full-ICU，前端 iOS 不可靠故走服务端）
  - `season`：花期季节顺序（春→夏→秋→冬，多季节取最早；知识库无具体月份字段）
  - `latest`：最近遇见时间倒序（未收集排最后）
  - `rarity`：稀有度降序（传说→珍稀→少见→常见），同级按中文名
  - 默认（`default`）：稀有度降序 + 中文名升序
- `stats` 基于全量知识库计算，不受筛选影响。
- **当前无分页**：全量下发 60 条 species + 用户全部卡片（规模小，可接受；增长后需改造）。

### 5.4 getAchievements — 等级与成就

**入参**：无

**返回**：`{ ok, level { name, count, nextName, nextMin, progress }, badges[], stats, todayUsed, todayLimit, todayRemaining, recentCards[] }`

- **等级**：按收集种数分 5 档：爱花萌新(1) / 拾花者(6) / 赏花人(16) / 花语师(31) / 花神(46)。
- **徽章**（9 枚，`BADGES` 数组）：初次识花、收集 5/10/25/50 种、收集率 50%/100%、四季拾花、首张传说卡。`achievedAt` 取触发条件的那张卡 `firstMetAt`。
- **稀有度分布** `rarityDist`：四档各自 total/collected。
- **今日次数**：读 `rate_limits` 当日文档。
- **recentCards**：已收集花卡按最近遇见时间排序前 6 张（含 `_id/cnName/latinName/rarity/illustrationFileID/meetCount/lastMetAt`），供首页单请求展示。

### 5.5 initSpecies — 知识库导入（管理员）

- 以 `species-data.js` 中 `id` 作为文档 `_id` 执行 `set()`，**幂等**，重复调用只覆盖。
- `ADMIN_OPENIDS` 环境变量（逗号分隔）配置白名单；**不配置则任何人可导入**（仅限开发期，README 已警示）。

### 5.6 deleteAccount — 注销账号

- 删除该 openid 的：全部 `user_cards`（先收集照片 fileID，按 50 个/批 `deleteFile`）→ 数据库花卡 → `photo_hashes` 指纹。
- **`rate_limits` 限流计数保留**（防恶意注销刷次数）：openid 不随注销改变，保留计数后注销无法刷新每日 20 次配额；历史记录仍由 `cleanupData` 按 30 天清理。
- 返回 `{ ok, deletedCards, deletedPhotos, deletedHashes, keptRateLimits: true }`；单类删除失败不阻断其余。
- 前端「我的」页入口：二次确认 + 输入「注销」确认词；提示文案明确「当日识别次数不会重置」。

### 5.7 cleanupData — 定时清理

- 定时触发器（config.json `triggers`，每周日 03:00，cron `0 0 3 * * 0 *`）。
- 清理 30 天前的 `rate_limits` 记录（date 为 yyyyMMdd 字符串，字典序比较）。
- 返回 `{ ok, removedRateLimits }`；循环分批删除（每轮 ≤1000 条，最多 100 轮防死循环）。

### 5.8 环境变量汇总

| 变量 | 所在函数 | 默认 | 说明 |
|---|---|---|---|
| `BAIDU_AK` / `BAIDU_SK` | recognizeFlower | 无 | 百度智能云密钥，必填 |
| `ENABLE_SEC_CHECK` | recognizeFlower | `true` | `false` 跳过内容安全检测 |
| `SEC_CHECK_STRICT` | recognizeFlower | `false` | `true` 时安全接口异常即拒绝 |
| `RECOGNIZE_DAILY_LIMIT` | recognizeFlower / getAchievements | `20` | 每日识别上限（两处均读环境变量，前端展示用服务端 todayLimit 下发） |
| `ADMIN_OPENIDS` | initSpecies | 空 | 导入白名单，逗号分隔 |

## 六、核心业务流程

### 6.1 识花入库（主链路时序）

```
用户点「拍照识花」
  → util.chooseOneImage（chooseMedia 优先，低版本降级 chooseImage）
  → 跳转 recognize 页（tempPath 路由参数）
  → compressImage：最长边 ≤1080、质量 75（同时满足百度 ≤4M 与 imgSecCheck ≤1M）
  → uploadImage：上传到云存储 user-photos/{ts}_{rand}.{ext}，得 fileID
  → recognizeFlower（限流 → 内容安全 → 百度识别 → 匹配）
  → 渲染 Top3 候选（默认选中第一个命中知识库的）
  → 用户确认 或 「没对上？手动查找」（前端基于全局缓存的 catalog 按中文名/别名搜索）
  → saveCard(action=create)：已收集则追加照片 + meetCount+1，否则新建
  → 成功态（新卡「🎉 收录成功」/ 重复「💮 再次遇见」）
```

### 6.2 花卡维护

- 追加照片：`detail` 页 → `saveCard(addPhoto)` → `meetCount+1`。
- 备注编辑：弹窗 `textarea`（前端 maxlength 200）→ `saveCard(updateNote)`。
- 删除：`deletePhoto`（按下标） / `deleteCard`，均有二次确认；删除后图鉴与成就实时回退。

### 6.3 成就推导（无状态计算）

`getAchievements` 每次读取全量 species + 用户全部 user_cards，实时计算等级/徽章/分布/次数。优点：无冗余状态、删除即回退；代价：每次请求 O(60+cards) 计算，数据增长后需缓存或落库。

## 七、前端架构

### 7.1 页面与导航

- tabBar 四页：识花(index)、图鉴(album)、成就(achievements)、我的(profile)。
- 非 tab 页：recognize（识花流程）、detail（花卡详情），均通过 `wx.navigateTo` 进入。
- `lazyCodeLoading: requiredComponents` 按需注入组件。

### 7.2 全局状态

- `app.globalData.catalog`：知识库目录缓存（含收集标记），图鉴页写入，识别页手动搜索复用；识别页在缓存为空时（分享直进/冷启动）自动拉取 `getCollection` 补缓存。

### 7.3 关键前端实现

| 模块 | 要点 |
|---|---|
| `utils/util.js` | 图片压缩（`wx.compressImage` 按比例降采样）、上传（随机文件名防冲突）、`callFunction` 统一错误处理、`chooseOneImage`（chooseMedia + chooseImage 降级）、`deleteCloudFile`、日期/稀有度工具 |
| `flower-card` 组件 | 稀有度边框 class 映射（observers 监听 species）、未收集显示「？+剪影锁定」、收集显示 `×meetCount`、lazy-load |
| recognize 页 | `phase` 状态机：idle → recognizing → result → success；`onLoad` 支持带图直达；同图 30s 去重；识别失败清理已上传文件；低置信度（<60%）提示 |
| index 页 | 单请求 `getAchievements`（含 recentCards）+ 5 秒节流；分享转发 |
| album 页 | 花期筛选走服务端（重新请求），状态筛选（全部/已收集/未收集）走客户端内存过滤 |
| detail 页 | 地点编辑弹窗（updateLocation）；照片追加走 `chooseOneImage`；分享花卡 |
| profile 页 | 限流文案绑定服务端 `todayLimit`；注销入口（二次确认 + 输入确认词） |

## 八、安全设计

| 层面 | 措施 |
|---|---|
| 身份 | 一律服务端取 `OPENID`，前端不传、不可伪造 |
| 数据隔离 | `user_cards` 按 openid 查询；保存/删除操作均校验归属 |
| 内容安全 | 识别链路与 `saveCard` 入库/追加照片均过 `imgSecCheck`（jpeg→png 重试、87014 拒绝、异常 fail-open/STRICT fail-closed） |
| 密钥 | 百度密钥仅环境变量；token 缓存于 `bd_token` 集合（Promise 锁防并发刷新） |
| 限流 | 每用户每日 20 次（事务化原子计数，并发不超限；服务端原因失败退款） |
| 输入校验 | 云函数层校验 note/location 长度、photoFileID 类型、photoIndex 整数 |
| 数据生命周期 | 删卡/删照片/识别失败均清理云存储文件；注销入口删除全部个人数据 |
| 存储权限 | 云存储需配置「仅创建者可读写」（默认是「所有用户可读」，部署必改） |

## 九、部署与运维

完整步骤见 [README.md](../README.md)「快速开始」，此处为运维速查：

1. **初始化顺序**：注册小程序 → 替换 AppID → 开通云开发 → 建 4 集合 → 部署 7 云函数（`cleanupData` 首次部署选「上传触发器」）→ 配 `BAIDU_AK/SK` → 配 `ADMIN_OPENIDS` → 调 `initSpecies` → 上传插画并回填 fileID。
2. **存储权限（必改）**：云开发控制台 → 存储 → 权限设置 → 「仅创建者可读写」，否则用户照片可被任何人通过 fileID 读取。
3. **环境变量改动**：修改后必须重新部署对应云函数。
4. **内容生产**：插画用 `scripts/seedream_generate.py`（即梦 Seedream）批量生成 → 上传云存储 `assets/species/` → `node scripts/fill_illustration_ids.js ids.json` 回填 → 重新导入。
5. **多环境**：`miniprogram/config.js` 的 `CLOUD_ENV` 支持指定环境 ID；建议开发/生产环境分离。
6. **监控**：云开发控制台可看云函数调用量/错误日志；建议配置错误率告警（评审 3.6）。
7. **索引**：数据增长后在控制台为 `user_cards` 建 `openid+speciesId` 联合索引（见 SCHEMA.md）。
