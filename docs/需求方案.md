## 一、产品定位

**一句话**：拍一朵花 → 识别它 → 收进你的水彩花田。

「随心一拍-花知道」是一个面向普通大众的**识花科普 + 收藏图鉴**微信小程序。以「拍照识花」为入口，以「水彩花卡收集」为核心玩法，以「图鉴收集率 + 成就徽章」为留存激励，用轻量、治愈、低门槛的方式满足用户「路边的花随手一拍就知道」的需求。

### 1.1 目标用户

| 用户群 | 特征 | 核心诉求 |
|---|---|---|
| 泛识花人群 | 日常在路边/公园/校园看到不认识的花 | 快速知道花名与基础科普 |
| 植物爱好者/轻度玩家 | 有记录欲、收集欲 | 收藏图鉴、记录遇见、解锁成就 |
| 亲子/科普场景 | 带孩子认识自然 | 科普档案（科属/花期/花语）可读性强 |

### 1.2 设计原则

1. **极简闭环**：拍 → 识 → 收三步走完，单次识别 ≤ 30 秒。
2. **游戏化收集**：稀有度（常见/少见/珍稀/传说）+ 水彩卡面 + 收集率，让收集有「集卡」的乐趣。
3. **克制与合规**：个人主体小程序，不做公开社区/评论/分享墙，规避 UGC 内容风险。
4. **数据自重**：用户照片仅本人可见，可删除；识别结果以用户确认为准。

## 二、核心玩法闭环

```
拍照/相册选图
   │
   ▼
AI 识别（百度植物识别，Top3 候选）──┬── 候选命中知识库 → 确认
   │                             └── 未命中/不确定 → 手动搜索纠正
   ▼
生成花卡入库（已收集则追加照片 + 「第 N 次遇见」）
   │
   ▼
图鉴收集（60 种，收集率%）→ 稀有度分布 → 花匠等级 → 成就徽章
```

## 三、功能需求

优先级定义：P0（核心闭环，缺则不可用）/ P1（重要体验）/ P2（增强项）。

### F-01 识花入口（P0）

| 项目 | 说明 |
|---|---|
| 入口 | 首页「拍照识花」「从相册选择」两个按钮；识别页内可重新选图；相册支持**多选批量**（≤5 张，见 [批量识别方案](批量识别方案.md)） |
| 能力 | `wx.chooseMedia`；拍照单张，相册多选（`count:5`）；图片最长边 ≤1080、质量 75 |
| 处理 | 前端压缩（最长边 ≤1080、质量 75）后上传云存储，再调识别 |
| 每日限流 | 每用户每日 20 次（首页/识别页/成就页/我的页均展示剩余次数） |

### F-02 识花识别（P0）

| 项目 | 说明 |
|---|---|
| 识别源 | 百度智能云「植物识别」，返回 Top 3 候选（含置信度、百度百科信息） |
| 候选展示 | 置信度百分比、命中知识库的显示花种信息（稀有度/科属/简介），未命中显示百科摘要 |
| 默认选中 | 自动选中第一个命中知识库的候选，避免误收未收录项 |
| 批量识别 | 相册多选 ≤5 张：逐张串行识别（云函数 20s 超时限制），统一清单逐张确认入库；失败张跳过标记、最后统一处理；中途退出保留已识别结果；未收录花批量生成（串行 + 配额提示 + 生成中置灰），详见 [批量识别方案](批量识别方案.md) |
| 失败兜底 | 识别失败/未识别出花时，可把照片保存到系统相册，或换一张重拍 |
| 提示 | 识别结果仅供参考，以用户确认为准 |

### F-03 候选确认与手动纠正（P0）

| 项目 | 说明 |
|---|---|
| 确认 | 选中候选 →「确认入库，生成花卡」 |
| 手动纠正 | 「没对上？手动查找」→ 按中文名/别名在前端缓存目录中搜索 → 选中后置顶为第一候选 |
| 去重 | 同一花种重复识别**不重复计收集数**：已收集则追加照片、`meetCount +1`，成功态提示「再次遇见」 |

### F-04 花卡与图鉴（P0）

| 项目 | 说明 |
|---|---|
| 花卡 | 水彩绘本风卡面 + 稀有度配色边框（常见绿/少见蓝/珍稀紫/传说金） |
| 未收集态 | 卡面剪影锁定、名称显示「？？？」，保留稀有度/花期等公共信息 |
| 图鉴页 | 统计卡（已收集/总数/收集率）+ 进度条；筛选：全部/已收集/未收集、花期（春/夏/秋/冬） |
| 排序 | 稀有度降序 + 中文名升序 |

### F-05 花卡详情（P0）

| 项目 | 说明 |
|---|---|
| 卡头 | 插画 + 名称 + 稀有度徽章 + 科属 |
| 遇见记录 | 遇见次数、首次遇见、最近遇见 |
| 拍摄记录 | 照片横向滚动；支持追加照片（自动计入遇见次数）、全屏预览、删除单张（二次确认） |
| 备注 | 卡片级备注编辑（≤200 字，如地点/心情/故事） |
| 科普档案 | 花期、花色、简介、识别特征、花语、养护、分布、趣味小知识（未收集也可查看） |
| 插画保存 | 点击插画全屏预览，长按保存到相册（与拍摄记录交互一致；未收集也可预览） |
| 删除 | 删除整卡（二次确认），图鉴/等级/徽章实时回退 |

### F-06 成就系统（P1）

| 项目 | 说明 |
|---|---|
| 花匠等级 | 5 档：爱花萌新(1) / 拾花者(6) / 赏花人(16) / 花语师(31) / 花神(46)，按收集种数，显示升级进度 |
| 成就徽章 | 33 枚：基础收集 9（初次识花 / 收集 5·10·25·50 种 / 收集率 50%·100% / 四季拾花 / 首张传说卡）+ 新收录花 6（收集 AI 新花 / 发起收录 / 首发见证）+ 花期 18（季节收集量 / 四季进阶 / 应季花信 / 四时象征花）；显示解锁时间。设计见 [成就系统扩展方案](成就系统扩展方案.md) |
| 稀有度收藏 | 四档稀有度各自的收集进度条 |
| 今日识花 | 剩余识别次数展示 |

### F-07 我的（P1）

| 项目 | 说明 |
|---|---|
| 数据总览 | 已收集、图鉴收集率、今日剩余识别 |
| 说明 | 识别能力来源、每日限额、数据隐私声明 |
| 隐私政策 | 应用内弹窗展示；公众平台侧另需配置《用户隐私保护指引》 |
| 意见反馈 | 「支持」区块入口：结构化表单（体验建议/问题反馈/其他 + 文字 ≤500 字 + 截图 ≤3 张）；用户可见历史反馈（分页）；每日 5 条限流；设计见 [意见反馈方案](意见反馈方案.md) |
| 版本信息 | 应用名 + 版本号 |

### F-08a 未收录花自动生成（v2，P1）

| 项目 | 说明 |
|---|---|
| 触发 | 识别未命中知识库且置信度 >40% 时，候选卡片显示「收录并生成花卡」，用户点击确认才触发 |
| 生成 | DeepSeek（deepseek-v4-flash）生成 15 字段科普 + Seedream（doubao-seedream-5.0-lite）生成水彩插画，异步任务制（约 1~2 分钟，前端轮询） |
| 发布 | 自动公开入库（`aiGenerated` 标记 + 全站「AI 生成」角标与免责提示） |
| 防滥用 | 每用户每日 3 次；同名任务去重复用；生成物过文本/图片内容安全检测 |
| 成本 | Seedream 免费 200 张后 0.2 元/张；DeepSeek 单次约 0.005 元 |

### F-08 知识库与内容生产（P0 支撑）

| 项目 | 说明 |
|---|---|
| 知识库 | 60 种国内常见花：中文名/学名/科属/稀有度/花期/花色/简介/识别特征/花语/养护/分布/趣味知识/别名 |
| 插画 | 统一水彩绘本风（即梦 Seedream 批量生成），每花一张，用于花卡卡面 |
| 导入 | `initSpecies` 云函数幂等导入，管理员白名单控制 |

## 四、玩法规则定义

| 规则 | 定义 |
|---|---|
| 稀有度 | 常见（绿）/ 少见（蓝）/ 珍稀（紫）/ 传说（金），知识库人工标注（当前 28/19/11/2） |
| 收集判定 | 每 openid + 花种一张卡；重复识别不重复计数，仅追加照片与「遇见次数」 |
| 遇见次数 | 每成功入库一次 +1（含首次），删除照片不减次数 |
| 花匠等级 | 按已收集种数实时推导，删除卡片自动降级 |
| 成就徽章 | 全部由收集状态实时推导，`achievedAt` 取触发条件达成时间 |
| 每日限流 | 20 次/人/天，按 openid+自然日计数，识别请求即计入（含失败） |
| 数据回退 | 删除花卡后，图鉴收集率、等级、徽章全部实时重算，无历史残留 |

## 五、非功能需求

### 5.1 性能

| 项 | 指标 |
|---|---|
| 单次识别耗时 | 理想 ≤ 8s（压缩上传 1~2s + 云函数链路 3~5s），超时给可理解的失败提示 |
| 图鉴加载 | 全量 60 条 ≤ 1s（当前规模）；用户卡片随使用增长需分页化 |
| 图片体积 | 上传前压缩至最长边 1080、质量 75（满足百度 ≤4M、内容安全 ≤1M） |

### 5.2 可用性

- 云函数统一 `{ ok, code, message }` 返回 + 前端统一错误提示，失败可重试。
- 关键操作（删除照片/删除花卡）二次确认。
- 用户取消选择相机/相册时不弹错误。

### 5.3 安全与合规（P0 级约束）

| 项 | 要求 |
|---|---|
| 身份隔离 | 所有数据按 OPENID 归属，服务端校验，前端不可传 openid |
| 内容安全 | 上传图片必须过微信内容安全检测（当前缺口：追加照片未检测，见评审文档） |
| 密钥管理 | 百度 AK/SK 仅存云函数环境变量，不进前端代码与仓库 |
| 数据隐私 | 照片存私有目录、仅本人可见；提供删除能力；隐私政策应用内展示 + 公众平台配置 |
| 账号注销 | 需提供用户数据删除/注销能力（当前缺失，隐私政策已承诺「后续提供」） |
| 类目与备案 | 个人主体按「工具-图片/摄影」类目申报；上线前完成 ICP 备案 |

### 5.4 兼容性

- 基础库 ≥ 2.2.3（`wx.cloud`）；`chooseMedia` 需较高基础库，低版本需降级 `chooseImage` 兜底（当前未做）。

## 六、数据需求

| 数据 | 内容 | 隐私等级 |
|---|---|---|
| 用户花卡 | openid、speciesId、照片 fileID、遇记录、备注 | 仅本人可见 |
| 识别照片 | 云存储 `user-photos/` 下的原图 | 仅本人可见（需确认存储权限） |
| 限流计数 | openid + 日期 + 次数 | 服务端内部 |
| 知识库 | 60 条花卉科普 + 插画 | 全员可读 |

以下字段/接口**已实现但无前端入口**（需求规划先于实现，属遗留项）：

| 项 | 现状 | 建议 |

## 九、关键决策记录（ADR 摘要）

| 决策 | 理由 |
|---|---|
| 云开发而非自建后端 | 免运维、免费额度、天然微信身份 |
| 百度植物识别而非自研模型 | 成本低、准确率高；Top3 + 人工确认弥补误识别 |
| 成就不落库、实时推导 | 删除即回退，杜绝数据不一致；规模小可承受计算成本 |
| 照片先上传后识别 | 云函数直接下载 fileID，避免前端传 base64（体积超限） |
| 限流按「请求即扣」 | 防滥用优先；代价是失败也扣次数（体验取舍，可优化为失败退次数） |
| 不做公开社区 | 个人主体 UGC 合规风险大，规避 |
