# 随心一拍-花知道 · 部署与验证手册

> 适用：首次上线 / 换环境 / 修复后重部署。配套 [修复与优化记录](修复与优化记录.md)。
> 本手册所有操作都在**微信开发者工具**与**云开发控制台**完成（需登录态），无法脚本化。

## 一、部署 7 个云函数

### 步骤

1. 打开微信开发者工具，导入项目根目录（`project.config.json` 已配置 `miniprogramRoot` / `cloudfunctionRoot`）。
2. 左侧资源管理器展开 `cloudfunctions/`，对以下 **7 个目录逐个右键 →「上传并部署：云端安装依赖」**：

   | 函数 | 本次是否修改 | 说明 |
   |---|---|---|
   | `recognizeFlower` | ✅ 修改 | 事务限流、失败退款、缓存、超时 20s |
   | `saveCard` | ✅ 修改 | 内容安全、删除清理、输入校验、照片上限 |
   | `getAchievements` | ✅ 修改 | 新增 recentCards |
   | `getCollection` | 未修改 | 建议重传保持线上一致 |
   | `initSpecies` | 未修改 | 建议重传保持线上一致 |
   | `deleteAccount` | 🆕 新增 | 注销账号 |
   | `cleanupData` | 🆕 新增 | 定时清理 |

3. **`cleanupData` 部署时勾选「上传触发器」**（config.json 中 `triggers` 为每周日 03:00 的 cron `0 0 3 * * 0 *`）。不勾选则定时任务不生效。

### 验证

- 云开发控制台 → 云函数：应看到 7 个函数，运行状态正常。
- `cleanupData` →「触发器」标签：存在 `weekly-cleanup`。
- `recognizeFlower` →「环境变量」：`BAIDU_AK` / `BAIDU_SK` 仍在（部署不覆盖环境变量，但需确认）。
- 可选：控制台 → 云函数 → `recognizeFlower` →「测试」，传入 `{ "fileID": "cloud://..." }` 验证链路。

## 二、云存储权限（必改，注意插画目录）

### 背景

- 云存储默认权限是「所有用户可读」——用户照片 fileID 一旦泄露可被任何人读取，**必须改**。
- 但**不能整体改成「仅创建者可读写」**：`assets/species/` 下的 60 张知识库插画需要**所有用户可读**（图鉴/识别页展示），只有 `user-photos/` 用户照片需要仅创建者可读。

### 操作（云开发控制台 → 存储 → 权限设置 → 自定义安全规则）

```json
{
  "read": "resource.path.startsWith('assets/species/') || resource.openid == auth.openid",
  "write": "resource.openid == auth.openid"
}
```

| 目录 | read 效果 | write 效果 |
|---|---|---|
| `assets/species/`（插画） | 所有用户可读 | 仅上传者可写 |
| `user-photos/`（用户照片） | 仅创建者可读 | 仅创建者可写 |

### 验证

1. 开发者工具用 A 账号（本人）收藏照片 → 能正常看图。
2. 用 **B 微信号**打开同一小程序 → 图鉴插画正常显示、A 的照片不可见（`user-photos` 下资源加载失败或访问被拒）。
3. 若插画改用 https URL（图床/CDN），规则可简化为：
   ```json
   { "read": "resource.openid == auth.openid", "write": "resource.openid == auth.openid" }
   ```

## 三、数据库索引（建议项）

云开发控制台 → 数据库 → 对应集合 → 索引管理 → 添加索引：

| 集合 | 索引字段 | 类型 | 用途 |
|---|---|---|---|
| `user_cards` | `openid`（升序）+ `speciesId`（升序） | 普通索引 | 花卡查询/去重（数据量增长后收益明显） |
| `rate_limits` | `date`（升序） | 普通索引 | `cleanupData` 清理扫描 `where({ date: _.lt(...) })` |

> 当前数据量小，不建索引也能工作；建议上线后用户量起来前建好。

## 五、未收录花自动生成部署（v2 新增）

> 功能说明见 [未收录花自动生成方案](未收录花自动生成方案.md)。识别未收录花（置信度 >40%）时用户可一键生成完整花卡。

1. **建集合**：云开发控制台 → 数据库 → 创建 `flower_gen_tasks`、`gen_limits`（权限「仅管理端可读写」）。
2. **部署云函数**：`requestFlowerGenerate`、`getFlowerGenerateTask`、`generateFlowerWorker`（**worker 首次部署勾选「上传触发器」**，每 2 分钟执行）。
3. **配置环境变量**（`generateFlowerWorker` → 配置）：
   | 变量 | 说明 |
   |---|---|
   | `DEEPSEEK_API_KEY` | DeepSeek 平台 API Key（必填） |
   | `ARK_API_KEY` | 火山方舟 API Key（必填，需开通 Seedream 视觉模型） |
   | `ARK_MODEL` | 可选，默认 `doubao-seedream-5.0-lite` |
   `requestFlowerGenerate` 可选 `GEN_DAILY_LIMIT`（默认 3）。
4. **验证**：识别一种 60 种知识库外的花（置信度 >40%）→ 候选出现「✨ 收录并生成花卡」→ 点击 → 约 1~2 分钟生成完成 → 确认入库 → 图鉴出现该花（带「AI 生成」角标）。
5. **成本**：Seedream 免费 200 张后 0.2 元/张；DeepSeek 单次约 0.005 元。

## 六、插画接入云存储（图鉴显示插画，手把手）

> 前提：`project.config.json` 已排除 `images/species` 打包（包体修复），插画只能走云存储展示。

1. **上传**：云开发控制台 → 存储 → 上传文件 → 全选 `miniprogram/images/species/` 下 60 张 jpg → 上传到 `assets/species/`（保持 `{id}.jpg` 原名）。
2. **复制 fileID**：文件列表 → 点 `yueji.jpg` →「复制 fileID」，得到形如 `cloud://cloud1-xxx.6565-yyyy/assets/species/yueji.jpg`。
3. **生成 ids.json**（自动，无需手动整理）：去掉 fileID 末尾 `/yueji.jpg` 得到目录前缀，项目根目录执行：
   ```powershell
   node scripts/gen_ids.js "cloud://cloud1-xxx.6565-yyyy/assets/species"
   ```
   输出 `已生成 60 条映射 -> ids.json`。
4. **回填**：`node scripts/fill_illustration_ids.js ids.json` → `已回填 60/60`。
5. **部署导入**：重新部署 `initSpecies`（右键 → 上传并部署）→ 小程序 Console 执行 `wx.cloud.callFunction({ name: 'initSpecies' })` → 返回「已导入 60 种花」。
6. **验证**：重新编译 → 图鉴/详情页显示插画；`getCollection` 返回的 `illustrationFileID` 非空。

> 文件清单见 `scripts/species_images_manifest.json`；想换图床可把 ids.json 里的 fileID 换成 https URL（`illustrationFileID` 两者都支持），注意存储权限规则里 `assets/species/` 前缀需公开。

## 七、常见问题排查

| 现象 | 排查 |
|---|---|
| 识别报「未配置 BAIDU_AK / BAIDU_SK」 | `recognizeFlower` 环境变量未配置或部署未生效，重新配置后重传 |
| 图鉴插画全挂 | 存储权限规则里 `assets/species/` 前缀放行缺失 |
| 追加照片报「图片读取失败」 | 存储权限 write 规则限制导致文件上传/读取异常，检查自定义规则 |
| 定时清理不执行 | `cleanupData` 部署时未勾选「上传触发器」，重新部署 |
| 注销后仍能查到数据 | 确认部署了 `deleteAccount` 且前端调用的是新函数名 |
