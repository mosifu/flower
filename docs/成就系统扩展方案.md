# 成就系统扩展方案（新收录花 + 花期成就）

> 状态：已实施（2026-08-16 设计定稿并实施完成，详见 [修复与优化记录](修复与优化记录.md)）
> 关联文档：[技术文档](技术文档.md)｜[需求方案](需求方案.md)｜[修复与优化记录](修复与优化记录.md)｜[SCHEMA.md](SCHEMA.md)

## 一、目标

在现有 9 枚成就徽章的基础上，新增两类成就：

1. **新收录花成就**：围绕「未收录花自动生成」（AI 生成新花，`aiGenerated: true`）这一 App 特色功能，奖励「收集新花」与「发起收录（贡献新花）」两类行为。
2. **花期成就**：围绕 `bloomSeasons`（春/夏/秋/冬）做深度化——从现有「四季拾花（各 1 种）」扩展出分季节收集量、四季进阶组合、真实时节的应季成就、四时象征花等。

全部徽章仍由 `getAchievements` **实时推导、不落库**（沿用现有设计：删除卡片自动回退）。

## 二、决策记录（已与用户确认）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 成就范围 | 新收录花（3 组）+ 花期（4 组）共 **24 枚新徽章**，与现有 9 枚共存 | 用户确认「全部都做」 |
| 判定方式 | 全部由 `getAchievements` 实时推导，`achievedAt` 取触发条件达成时间 | 与现有徽章一致，删除即回退 |
| 新数据源 | 新收录花相关需新增查询 `flower_gen_tasks`（发起收录计数） | 现有逻辑只读 `species` + `user_cards`，需扩展 |
| 季节判定口径 | 沿用 `bloomSeasons` **包含**匹配（多季节花各季节都计入），与图鉴花期筛选一致 | 与现有 `four_seasons` 一致，避免口径冲突 |
| 应季成就口径 | 以「真实季节」（按当前月份）匹配「收集该花时的真实季节」，需要花的 `firstMetAt` 落在其 `bloomSeasons` 对应的真实季节 | 鼓励用户在当季去拍当季的花 |
| 门槛设计 | 贴合各季节可收集种数（春 37 / 夏 32 / 秋 19 / 冬 5），冬季门槛最低 | 保证可达成性，冬季最稀有 |
| 首发见证口径 | 「首位收录发起人」= 该花 `flower_gen_tasks` 中最早完成（done）的任务的 `openid` | 同名任务去重 + 已入库校验下，通常只有一人发起生成 |

- `user_cards.firstMetAt`：该花首次收录时间（用作 `achievedAt`）
- `flower_gen_tasks`：`{ openid, name, status, speciesId, createdAt }`，`status=done` 且 `speciesId` 非空表示该用户成功发起生成并收录了一种新花

## 五、判定逻辑详述

> 以下均以 `getAchievements` 现有入参为准：`speciesList`（全量启用 species）+ `cardBySpecies`（当前用户花卡索引）+ `collected`（已收集 species 数组）。

### 5.1 通用口径

- **新收录花** = `s.aiGenerated === true` 的 species。
- **季节包含** = `(s.bloomSeasons || []).includes(季节)`，多季节花各季节都计入（与 `four_seasons`、图鉴花期筛选一致）。
- **achievedAt 取值**：收集类取「触发该徽章的那张卡」的 `firstMetAt`（按 `firstMetAt` 升序取第 N 个）；组合类取最后一个满足条件的时刻。

### 5.2 Track A：收集 AI 新花（new_collect_1 / 5 / 10）

```
const newCollected = collected.filter(s => s.aiGenerated);
newCollected.sort((a,b) => cardBySpecies[a._id].firstMetAt - cardBySpecies[b._id].firstMetAt);
unlocked = newCollected.length >= N;
achievedAt = newCollected[N-1] 的 firstMetAt;
```

### 5.3 Track B：发起收录（contributor_1 / 5）

新增查询 `flower_gen_tasks`（当前 openid、`status=done`、`speciesId` 非空），按 `createdAt` 升序取前 N 个：

```
const myDone = (await db.collection('flower_gen_tasks')
  .where({ openid: OPENID, status: 'done' })
  .orderBy('createdAt', 'asc').limit(1000).get()).data
  .filter(t => t.speciesId);
unlocked = myDone.length >= N;
achievedAt = myDone[N-1].createdAt;
```

> 说明：`flower_gen_tasks._id = "{openid}_{normalizedName}"`，同用户同花名只有一条任务记录，`status=done` 即代表该用户成功发起收录了这一种新花。

### 5.4 Track C：首发见证（first_discoverer）

对当前用户每条 `done` 任务（含 `speciesId`）的花，判断「该花最早完成的任务 openid 是否等于我」：

```
for (const t of myDone) {
  const first = (await db.collection('flower_gen_tasks')
    .where({ speciesId: t.speciesId, status: 'done' })
    .orderBy('createdAt', 'asc').limit(1).get()).data[0];
  if (first && first.openid === OPENID) { unlocked = true; achievedAt = first.createdAt; break; }
}
```

> 边界：由于 `requestFlowerGenerate` 同名去重 + 「花已入库即返回 alreadyExists」，正常情况同一花只有一位发起人，`first_discoverer` 与 `contributor_1` 基本同时达成；保留并发竞态下的兜底判断。若任务数较多可改为「对每个 speciesId 缓存最早任务」。

### 5.5 季节收集量（spring_3/10/20、summer_3/10/20、autumn_3/10、winter_1/3）

按季节过滤 + 按 `firstMetAt` 升序取第 N 个：

```
const inSeason = collected.filter(s => (s.bloomSeasons || []).includes('春'));
inSeason.sort((a,b) => cardBySpecies[a._id].firstMetAt - cardBySpecies[b._id].firstMetAt);
unlocked = inSeason.length >= N;
achievedAt = inSeason[N-1] 的 firstMetAt;
```

### 5.6 四季进阶组合（seasons_2x、seasons_master）

对每个季节分别算出「达到要求收集数所需的那张卡」的时刻，取最大值作为 `achievedAt`：

```
const seasonThreshold = { 春: 2, 夏: 2, 秋: 2, 冬: 2 };  // seasons_2x
const seasonThreshold = { 春: 10, 夏: 8, 秋: 5, 冬: 3 };  // seasons_master
const times = [];
for (const [season, need] of Object.entries(seasonThreshold)) {
  const arr = collected.filter(s => (s.bloomSeasons || []).includes(season))
                       .map(s => cardBySpecies[s._id].firstMetAt)
                       .sort((a,b) => a - b);
  if (arr.length < need) { unlocked = false; break; }
  times.push(arr[need - 1]);
}
unlocked = times.length === 4;
achievedAt = unlocked ? Math.max(...times) : 0;
```

### 5.7 应季花信（in_season_first、season_cycle）

需要「真实季节」与「收集时间所在季节」同时匹配花的 `bloomSeasons`：

```
function monthSeason(m) { return m>=3&&m<=5?'春' : m>=6&&m<=8?'夏' : m>=9&&m<=11?'秋' : '冬'; }

const inSeasonMets = cards.map(c => ({
  season: monthSeason(new Date(c.firstMetAt).getMonth() + 1),
  firstMetAt: c.firstMetAt,
  blooms: (speciesById[c.speciesId].bloomSeasons || []).includes(monthSeason(new Date(c.firstMetAt).getMonth() + 1))
})).filter(x => x.blooms);

unlocked = inSeasonMets.length >= 1;
achievedAt = Math.min(...inSeasonMets.map(x => x.firstMetAt));
```

`season_cycle`：四个真实季节都要有「当季收集且花期覆盖当季」的花：

```
const covered = new Set(inSeasonMets.map(x => x.season));
unlocked = ['春','夏','秋','冬'].every(s => covered.has(s));
achievedAt = Math.max(...['春','夏','秋','冬'].map(s =>
  Math.min(...inSeasonMets.filter(x => x.season === s).map(x => x.firstMetAt))));
```

> 注意：season_cycle 本质是「跨一整年」的长期成就，最短也要在真实的四个季节各收集一朵当季花，无法一天内达成。

### 5.8 四时象征花（season_flower_*）

```
unlocked = !!cardBySpecies['yingchunhua' | 'hehua' | 'juhua' | 'meihua'];
achievedAt = cardBySpecies[花种id].firstMetAt;
```

## 九、风险与回退

| 风险 | 对策 |
|---|---|
| 新徽章过多（33 枚） | 徽章墙为网格渲染天然支持；如需可按「新花 / 四季 / 应季」分组展示（前端增强，待后续） |
| `flower_gen_tasks` 查询增加 | 仅按 openid 查询，规模小；`first_discoverer` 对每条任务单查可改为按 speciesId 分组后一次查 |
| 冬季门槛（3 种）过难 | 冬季仅 5 种；若用户反馈过难，可下调为 `winter_3 → winter_2` |
| `season_cycle` 跨年漫长 | 属预期（长期留存）；若担心用户流失可增加中途提示（前端增强） |
| AI 新花扩充导致季节总量变化 | 门槛基于「当前总量」设计，成长型可接受；未来可在 `miniprogram/config.js` 收敛阈值配置 |
