# 未收录花自动生成方案（识花补录：LLM 科普 + AI 插画）

> 状态：设计定稿（2026-08-13 与用户讨论确认），待实施
> 关联文档：[技术文档](技术文档.md)｜[需求方案](需求方案.md)｜[修复与优化记录](修复与优化记录.md)

## 一、目标

识别到图鉴未收录的花时，用户可一键触发：
**DeepSeek LLM 生成完整科普信息 + Seedream 生成水彩插画 → 自动公开入库 → 该花立即可收集**；
此后任何用户识别到同一种花直接命中知识库，无需再次生成。

## 二、决策记录（已与用户确认）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 触发方式 | **用户点击「收录并生成」才触发**（识别置信度 >0.4（40%）才显示按钮） | 防滥用、控成本（用户调整：阈值 0.6 → 0.4） |
| 科普信息 | **DeepSeek LLM** 按知识库 schema 生成（模型 `deepseek-v4-flash`） | 完整 15 字段 |
| 插画 | Seedream **agentplan 视觉模型 `doubao-seedream-5.0-lite`**，接口 `https://ark.cn-beijing.volces.com/api/plan/v3/images/generations` | 风格与现有 60 张一致（风格提示词模板复用） |
| 发布策略 | 生成完成**自动公开入库**，打 `aiGenerated` 标记 + 前端「AI 生成」角标 | 即时可用，质量靠角标与后续人工修正 |
| 生成配额 | 每用户每日 3 次；同名任务去重复用 | 控制成本 |

## 三、系统流程

```
识别未命中 + score>0.4（40%）
   │ 前端候选卡片下显示「收录并生成花卡」按钮
   ▼
用户点击
   │
   ├─① requestFlowerGenerate（秒回）：每日配额校验 → 同名任务去重 → 建任务 → 返回 taskId
   │
   ├─② 前端「生成中」状态：文案「正在绘制插画与撰写科普，约需 1 分钟」，每 4s 轮询
   │
   ├─③ generateFlowerWorker（定时触发器每 5 分钟，参考 cleanupData 模式）：
   │     1. 取 pending 任务（每轮最多 3 个，防超时）→ 置 generating
   │     2. DeepSeek 生成科普（严格 JSON 输出，parse 失败重试 1 次）
   │     3. Seedream 生成插画 → 下载 → 上传云存储 assets/species/{id}.jpg
   │     4. 文本 msgSecCheck + 图片 imgSecCheck（生成物同样要过内容安全）
   │     5. 写入 species（aiGenerated: true）→ 任务置 done
   │
   └─④ 前端轮询到 done → 该花已入库 → 自动转为可确认候选 → 用户确认入库收集
        （失败 → 提示 + 退还当日生成配额，可重试）
```

## 四、新增/改动清单

| 组件 | 类型 | 说明 |
|---|---|---|

## 五、关键实现细节

### 5.1 flower_gen_tasks 集合

```
_id: "{openid}_{normalizedName}"   # 同名去重：同用户同花名 pending/generating 时复用任务
openid: string
name: string          # 百度识别返回的花名（原样，作为生成后 cnName 保证下次命中）
score: number         # 置信度
baikeUrl: string      # 百度百科链接（生成信息时可作为参考资料传给 LLM）
status: string        # pending → generating → done / failed
speciesId: string     # done 后回填
error: string         # failed 原因
createdAt / updatedAt: number
```

### 5.2 DeepSeek 调用（generateFlowerWorker 内）

- `DEEPSEEK_API_KEY` 环境变量；模型 **`deepseek-v4-flash`**（用户指定）；HTTP POST（参考 recognizeFlower 的 httpJson 模式）
- System prompt 要素：
  1. 输出**严格 JSON**：15 个字段（id/cnName/latinName/family/genus/rarity/bloomSeasons/colors/description/features/flowerLanguage/careTips/distribution/funFact/synonyms）
  2. `cnName` 用百度返回名**原样**（保证 matchSpecies 下次命中）；`synonyms` 补常见别名
  3. `rarity` 按常见程度判定（common/rare/epic/legendary，默认 rare）
  4. 语言风格对齐现有 60 种：轻松科普、人文气息、每个字段 1~2 句话
  5. 附百度百科描述作参考（有则传）
- JSON parse 失败 → 重试 1 次；仍失败 → 任务 failed
- 缺字段兜底空串（前端已兼容「—」展示）

### 5.3 Seedream 生图（generateFlowerWorker 内）

- 环境变量 `ARK_API_KEY`（火山方舟）、`ARK_MODEL`（默认 **`doubao-seedream-5.0-lite`**，用户指定）
- 接口地址：**`https://ark.cn-beijing.volces.com/api/plan/v3/images/generations`**（agentplan 视觉接口，与本地脚本 `scripts/seedream_generate.py` 使用的 `/api/v3/images/generations` 不同，实施时以该接口实际请求/响应格式为准）
- 提示词 = `scripts/species_prompts.json` 的风格前缀 + 花名 + 特征短语（LLM 生成的 features 或百科描述）
- 返回 base64/URL → 下载 → `cloud.uploadFile` 到 `assets/species/{speciesId}.jpg`
- 失败重试 1 次 → 任务 failed

### 5.4 生成物内容安全（必须）

- 文本：`msgSecCheck`（description / features / funFact 等）——不通过任务 failed
- 图片：`imgSecCheck`（与 saveCard 同款实现）——不通过任务 failed
- 违规不重试（避免反复生成违规内容），配额不退还

### 5.5 配额与去重

- `gen_limits`：`{openid}_{日期}` 计数，默认每日 3 次（环境变量 `GEN_DAILY_LIMIT` 可调）
- 配额在**建任务时**扣；任务 failed（非违规）→ 退还
- 同名去重：同 openid + 同花名存在 pending/generating → 直接返回已有 taskId，不重复扣配额
- 花已入库后（任何人生成过）→ 后续识别直接命中，不再出现生成入口

### 5.6 环境变量汇总

| 变量 | 所在函数 | 默认 | 说明 |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | generateFlowerWorker | 无（必填） | DeepSeek API Key |
| `ARK_API_KEY` | generateFlowerWorker | 无（必填） | 火山方舟 API Key（Seedream） |
| `ARK_MODEL` | generateFlowerWorker | doubao-seedream-5.0-lite | 生图模型（agentplan 视觉） |
| `GEN_DAILY_LIMIT` | requestFlowerGenerate | 3 | 每用户每日生成上限 |

### 5.7 前端交互（recognize 页）

- 候选未命中（`species: null`）且 `score > 0.4`（40%）→ 候选卡片显示「收录并生成花卡」按钮
- 点击 → 调 requestFlowerGenerate → 转「生成中」态（禁用其它操作）→ 每 4s 轮询（最多 3 分钟，约 45 次）
- done → 重新拉 getCollection 取该花 → 挂到候选（species 非空）→ 恢复可确认状态
- failed → 弹失败原因，可重试（非违规场景配额已退还）
- 超时未完成 → 提示「生成较慢，稍后在图鉴查看」+ 后台继续（任务仍会完成）

## 六、成本估算（单次生成）

| 项 | 成本 |
|---|---|
| Seedream 插画 | 免费额度 200 张内 0 元；超出 0.2 元/张 |
| DeepSeek 科普 | 每次约 2~3K tokens，约 0.005 元（几乎可忽略） |
| 云函数/数据库 | 免费额度内 |

## 七、合规注意

- **AI 生成标识**：插画与科普文案打「AI 生成」角标（生成式 AI 内容管理规定 + 微信规范）
- **生成物内容安全**：入库前文本/图片双检（5.4）
- **隐私政策更新**：说明「识别未收录花时，经用户确认后会将花名与百科资料发送给 DeepSeek 用于生成科普内容」
- 百度百科信息使用：详情页已有「来源：百度百科」标注惯例，生成信息若引用百科需同样标注

## 九、风险与回退

| 风险 | 对策 |
|---|---|
| DeepSeek JSON 输出不稳定 | 强约束 prompt + parse 重试 + 字段缺省兜底 |
| Seedream 生成失败率高 | 重试 1 次后 failed，不阻塞主流程 |
| 生成内容质量差 | `aiGenerated` 标记 + 后续用 initSpecies 模式做单条人工修正覆盖 |
| 成本失控 | 每日 3 次/人 + 同名去重 + 置信度阈值三重闸门 |
