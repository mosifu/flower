# 识别任务后台化方案（批量确认入库转云端后台执行 + 首页识别任务模块）

> 状态：已实施（2026-08-17 设计定稿并实施完成，详见 [修复与优化记录](修复与优化记录.md)）
> 关联文档：[技术文档](技术文档.md)｜[需求方案](需求方案.md)｜[批量识别方案](批量识别方案.md)｜[SCHEMA.md](SCHEMA.md)｜[修复与优化记录](修复与优化记录.md)

## 一、目标

解决批量识别含未收录花时「用户只能呆在识别页等待生成（可能 1~10 分钟）」的体验问题：

1. 点「确认全部入库」→ 提示「正在生成入库中，可回首页操作」→ 任务转为**云端后台执行**（关掉小程序也继续）；
2. 首页新增**「识别任务」模块**（位于「我的花田」下方、「识花时间线」上方），查看进行中/历史任务；
3. 任务详情页展示该批次结果（布局参考识别页），「确认全部入库」变为「查看识花结果」按钮，点击才跳收录成功界面。

## 二、决策记录（已与用户逐项确认）

| 决策点 | 选择 |
|---|---|
| 后台机制 | 新集合 `batch_tasks` + 新云函数 `batchSaveWorker`（定时每 1 分钟） |
| 批次命名 | 按时间：`YYYY-MM-DD_HH-mm-ss`（如 2026-08-17_14-30-25） |
| 任务列表 | 任务模块分「正在识别」「识别历史」两部分；无进行中任务显示「暂无识别任务」 |
| 任务详情 | 独立新页面（布局参考识别页），原批量结果区改展示识别批次时间 |
| 花状态 | 简单两态：已入库=已完成；未入库=生产中（转圈） |
| 任务完整性 | **任务 items 包含该批次全部照片**（含已秒入库的已收录花），详情页完整展示每一张，与识别清单界面一致 |
| 查看结果 | 有花已入库即可点「查看识花结果」，点击时提示「还有 N 朵在入库中」；后续成功花持续更新结果 |
| 数据保留 | 任务保留 7 天，`cleanupData` 定时清理 |
| 首页空态 | 无任务显示「暂无进行中的识别任务」；有任务显示「正在识别：<批次名>」 |
| 并发上限 | 进行中任务最多 **3 条**；达上限时照片识别/相册上传需提示「识别任务已达上限，请稍后再试」 |

## 三、数据模型（新集合 batch_tasks）

```
_id: string            # 自动生成
openid: string        # 任务归属用户
batchName: string     # 批次名 YYYY-MM-DD_HH-mm-ss（用户可见标识）
status: string        # pending（等待处理）/ processing（处理中）/ done（全部完成）/ partial（部分完成）/ failed
items: [{             # 每张照片的入库子任务
  fileID: string,    # 该张照片云存储（后台 saveCard 用）
  speciesId?: string,# 已收录花种 id（识别命中）；未收录为空
  name?: string,     # 未收录花百度名（生成用）
  score?: number,    # 未收录置信度
  baikeDesc?: string,# 未收录百科描述（生成用）
  itemStatus: string,# pending / generating（未收录生成中）/ done（已入库）/ fail
  meetCount?: number,# 入库后回填
  newCard?: boolean, # 入库后回填
  failMsg?: string   # 失败原因
}],
createdAt / updatedAt: number
```

## 四、云函数（3 个新增/改动）

### 4.1 createBatchTask — 创建识别任务（前端确认入库时调用）

**入参**：`{ items: [{ fileID, speciesId?, name?, score?, baikeDesc? }] }`

**流程**：
1. 校验：openid、items 非空、fileID 必填、每项物种信息合法；
2. **并发上限校验**：当前 openid 进行中任务（pending/processing）数 >= 3 → 返回 `TASK_LIMITED`；
3. 生成批次名 `YYYY-MM-DD_HH-mm-ss`；
4. 入库 `batch_tasks`（status=pending），返回 `{ taskId, batchName }`。

### 4.2 getBatchTask — 查询任务（首页模块/任务列表/详情轮询）

**入参**：`{ taskId?, status? }`（不传 taskId 返回当前用户全部任务，按 createdAt 倒序）

**返回**：`{ ok, list[] }` 或 `{ ok, task }`；list 含 `{ taskId, batchName, status, itemCount, doneCount, createdAt }`；
task 含完整 items（含每项 itemStatus/meetCount/newCard）。

### 4.3 batchSaveWorker — 后台处理（定时每 1 分钟）

**流程**（每轮取 N 个 pending/processing 任务，逐个处理 items）：
1. 取待处理任务：`status: pending` 优先，其次 `processing` 且更新超过 60s（防重入）；
2. 对每个 item：
   - **已收录花**（speciesId 有值）：调 saveCard(create)（同一 openid）→ 成功 itemStatus=done 回填 meetCount/newCard；失败 itemStatus=fail；
   - **未收录花**（speciesId 空）：若尚无生成任务 → 建 `flower_gen_tasks`（走 requestFlowerGenerate 逻辑，扣生成配额）；置 itemStatus=generating；
      下一轮查 `flower_gen_tasks` 状态：done → saveCard 入库置 done；failed → itemStatus=fail；
3. 每处理一个 item 更新任务 updatedAt；全部 item 终态 → 任务 status = done（全成功）/ partial（有 fail）/ failed（全 fail）；
4. 单轮受云函数超时限制（60s），处理不完的任务保留 processing 下轮续跑（updatedAt 防重入）。

## 五、前端交互

### 5.1 首页「识别任务」模块（index.wxml，位于我的花田下方、时间线上方）

- 无进行中任务：显示「暂无进行中的识别任务」（灰字）；
- 有进行中任务：显示「正在识别：2026-08-17_14-30-25」+ 轻量进度（x/N 完成）；
- 点击模块 → 跳转任务列表页 `pages/task-list/`。

### 5.2 任务列表页（pages/task-list/）

两部分：
- **正在识别**：进行中任务（pending/processing）卡片（批次名 + 进度 + 状态）；
- **识别历史**：已终态任务（done/partial/failed）卡片（批次名 + 结果摘要）；
- 无进行中任务时该区块显示「暂无识别任务」。

### 5.3 任务详情页（pages/task-detail/，独立页面，布局参考识别页）

- 顶部：批次名（识别批次时间，替代原批量结果标题）；
- **完整展示该批次全部照片**（含已秒入库的已收录花，不因入库完成而从任务移除），与识别清单界面一致；
- 每张照片：三列布局（照片 | 候选名+状态 | 提示区）——**状态简单两态**：
  - 已完成（itemStatus=done）：✓ + 花名 +「已完成」；
  - 生产中（generating/pending）：转圈 +「生产中」；
  - 失败（fail）：❌ + 原因；
- 底部按钮 **「查看识花结果」**：
  - 有花已入库（doneCount>0）即可点击 → 弹出提示「还有 N 朵在入库中」→ 确认后展示成功结果界面（swiper 展示已收录花，可左右切换，含「第 N 次遇见」）；
  - 后续新花成功（轮询 getBatchTask 更新）→ 结果界面自动追加；
- 页面轮询：进入时 + 每 5s 查一次 getBatchTask，更新状态直到全部终态。

## 六、并发上限与入口拦截

- 进行中任务上限 **3 条**（createBatchTask 服务端强制）；
- 前端入口（首页从相册选择/识别页批量识别）在创建任务前先查进行中任务数，>=3 提示「识别任务已达上限（3 条），请稍后再试」；
- 服务端 createBatchTask 二次校验兜底（返回 `TASK_LIMITED`）。

## 七、数据保留与清理

- `cleanupData` 扩展：清理 `batch_tasks` 中 `createdAt` 超过 7 天的记录（status 为终态；进行中的不清理，避免误删）；
- 任务完成后用户可随时查看历史（7 天内）；

## 八、现有批量识别流程的衔接

- `recognize.js` `processBatchInOrder` 改为：点「确认全部入库」→ 调 `createBatchTask` 建任务 → 提示「正在生成入库中，可回首页操作」→ 返回首页（不再页面内串行等待）；
- 原页面内生成轮询逻辑（pollBatchGenTask 等）不再用于批量入库路径（保留单图未收录花生成入口用）；
- 识别次数/生成配额在识别与建任务时已扣，后台 saveCard/生成沿用现有限流逻辑。

## 九、实施顺序

| 阶段 | 内容 |
|---|---|
| 1 | 集合 batch_tasks + 云函数 createBatchTask / getBatchTask / batchSaveWorker（定时 1 分钟） |
| 2 | 前端 index 识别任务模块 + 任务列表页 + 任务详情页（查看识花结果） |
| 3 | recognize 确认入库改建任务；入口并发拦截 |
| 4 | cleanupData 7 天清理 + 部署验证 + 文档同步 |

## v2 需求补充（2026-08-17 二次确认，实施中并入）

### 一、核心原则：识别有记录

- **只要识别（进入识别结果/清单界面）就创建识别任务**——单图与批量都算，与是否入库无关；
- 单图识别已收录花直接入库 → 也生成识别任务，状态「已完成」（全部入库）；
- 批量识别界面等待全部入库（不退出）→ 那次识别同样有任务记录。

### 二、任务状态机（三态）

| 状态 | 含义 | 详情页主体 | 底部按钮 |
|---|---|---|---|
| `identified` | 已识别未入库 | 识别结果界面（照片+**全部候选单选**+可预览照片） | 「确认入库」 |
| `processing` | 识别中（后台入库） | 照片+入库状态列表（已完成✓/生产中/失败） | 无完成：「识别中」（置灰）；有部分完成：「识别中，可查看部分结果」→ 进结果界面（已收录 swiper + 下方提示未入库，持续更新） |
| `done` / `partial` / `failed` | 全部入库（或部分/失败） | 同上 | 「查看结果」→ 完整识别结果界面 |

### 三、数据模型变化（batch_tasks.items）

```
items: [{
  fileID: string,
  status: 'identified' | 'pending' | 'generating' | 'done' | 'fail' | 'nonPlant' | 'duplicate',
  candidates: [{ name, score, scoreText, species, baike }],  # identified 阶段存全部候选（用户可操作）
  selectedIndex: number,   # identified 阶段用户当前选中
  # 确认入库后锁定，回填：
  speciesId: string,       # 选中候选的物种（已收录）；未收录为空
  name/score/baikeDesc: 未收录花生成用（锁定后回填）
  meetCount/newCard/failMsg: 入库后回填
}]
```

- `identified` 状态**存全部候选**（用户详情页仍可单选）；点「确认入库」后**锁定**，只存选中项；
- **identified 详情页可编辑**（复用识别结果界面交互，2026-08-17 用户确认）：重复照片可重新上传/继续识别/删除，非植物可重新上传/删除，已识别花可切换候选；编辑后 `updateBatchTask sync` 同步任务；
- `nonPlant`（未识别出花朵/非植物）与 `duplicate`（重复照片）在任务中如实记录，确认入库时跳过。

### 四、非植物 / 重复照片处理

- 判定：`hit=false` 且候选均无 species → `nonPlant`（提示「暂未识别出花朵」）；单图同样处理；
- 批量清单：nonPlant/重复 → 提示区「删除 + 重新上传」；重复照片**保留「继续识别」**并**新增「重新上传」**；
- 单图：nonPlant → 「暂未识别出花朵」提示 + 「重新上传」（无删除，单图无清单概念）；
- 兜底：确认入库跳过 nonPlant/duplicate/fail 张 + 提示「有 N 张未识别出花朵，未入库」。

### 五、未收录花生成入口降级为纯提示

- 批量清单 / 单图结果 / identified 详情：未收录花「收录并生成花卡」按钮**保留样式、取消功能**（仅提示）；
- 统一：确认入库时转后台生成（worker 自动建生成任务 → 完成入库）。

### 六、identified 任务创建与实时同步

- 识别完成进入结果/清单界面即创建 identified 任务；**批量识别刚开始即创建占位任务（incomplete），逐张识别结果实时回填——识别中断也保留已识别部分**（2026-08-17 用户确认）；
- 清单界面任何操作（重传/删除/重新识别/切换候选/删非植物）**实时同步**任务（调 updateBatchTask）；
- 用户点「确认入库」：任务存在则更新为 pending（不新建）；否则新建；
- 单图：已收录花直接入库 → 任务标记 done；未收录花 → 更新为 pending 转后台。

### 七、云函数变更

- `createBatchTask`：支持创建 identified 任务（items 含全部候选）；**并发上限仅统计 pending/processing（后台执行任务 ≤3 条），identified（识别记录）不占名额**（2026-08-17 测试反馈修正：原把 identified 计入上限，导致累积 ≥3 条后新识别无法创建任务）；
- 新增 `updateBatchTask`：identified→pending（锁定选中项）/ 实时同步清单 / 单图已收录标记 done；
- `getBatchTask`：返回 items 时含 candidates（详情页识别结果界面用）；
- `batchSaveWorker`：跳过 nonPlant/duplicate item；其余处理不变。
