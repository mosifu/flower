# 相册多选批量识别方案（单次 ≤5 张，逐张串行）

> 状态：已实施（2026-08-16 设计定稿并实施完成，详见 [修复与优化记录](修复与优化记录.md)）
> 关联文档：[技术文档](技术文档.md)｜[需求方案](需求方案.md)｜[未收录花自动生成方案](未收录花自动生成方案.md)｜[修复与优化记录](修复与优化记录.md)

## 一、目标

从相册**多选**（单次 ≤5 张）一次性识别多张照片：逐张串行识别 → 批量完成后统一列清单确认入库；
识别失败的单张跳过并标记，最后统一处理；识别中途退出时已识别结果保留；
兼容**未收录花（新物种）**的批量生成与收录。

## 二、决策记录（已与用户确认）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 批量上限 | 单次 ≤5 张 | 用户确认；受每日 20 次识别 + 体验平衡 |
| 识别方式 | 逐张串行（每张调一次 recognizeFlower） | 云函数 20s 超时限制，一次调用处理多张必超时；单张约 3~5s |
| 结果确认 | B：批量识别完统一列清单，逐张确认入库 | 用户确认；一次看全、操作集中 |
| 识别失败 | 跳过并标记「识别失败」，继续下一张，最后统一提示 | 用户确认；不中断批量 |
| 中途退出 | 已识别结果保留（已入库的花不受影响） | 用户确认；退出只丢弃未完成部分 |
| 选图来源 | 仅相册多选（拍照仍单张） | 用户指定「从相册选择时添加多选」 |

## 三、现状与约束（决定方案边界）

| 维度 | 现状 | 对批量方案的约束 |
|---|---|---|
| 每日识别上限 | 20 次/人/天（`RECOGNIZE_DAILY_LIMIT`，云函数事务强制） | 批量 N 张 = 消耗 N 次；选图时按剩余次数截断 |
| 云函数超时 | recognizeFlower 20s（config.json） | 单次调用只能处理 1 张；批量必须逐张串行调用 |
| 单张识别耗时 | 约 3~5s（下载 + 安全检测 + 百度识别） | 5 张约 15~25s，需进度反馈 |
| 单图压缩 | 最长边 ≤1080、质量 75 | 每张都过压缩（复用 util.compressImage） |
| MD5 去重 | 同图重复不扣次数 | 批量中重复图仍走去重弹窗逻辑 |
| 选图 | `chooseOneImage` count:1 | 需新增多选入口（`wx.chooseMedia` count:5） |
| 未收录花生成 | 单图触发「收录并生成花卡」，worker 每 2 分钟处理 1 个任务，每日生成上限 3 次 | 批量新物种须串行生成 + 配额提示（见第六节） |

## 四、交互设计

### 4.1 入口

- 首页 / 识别页「从相册选择」按钮：改用多选（`wx.chooseMedia` `count: 5`、`mediaType: ['image']`、`sourceType: ['album']`）；
- 选择后校验：`min(选中数, 剩余识别次数)`，超出部分提示并截断（例：剩 12 次选 5 张 → 全部识别；剩 3 次选 5 张 → 只识别前 3 张并提示）；
- 拍照入口保持单张（`sourceType: ['camera']`）。

### 4.2 批量识别进度

- 选中 N 张 → 进入 `phase: 'batch'` 批量识别页（新态）；
- 逐张串行识别：进度「3/5 识别中…」+ 当前张缩略图；
- 每张：压缩上传 → `recognizeFlower` → 结果暂存；
- 失败张：标记「识别失败」跳过，继续下一张；
- 全部完成（或全部失败）→ 进入清单确认页。

### 4.3 统一清单确认（方案 B）

识别完成后，按原顺序列出每张：

```
┌────────────────────────────┐
│ 📷 批量识别结果（5 张）       │
│ ┌────────────────────────┐ │
│ │ [缩略图] 月季 · 98.2%     │ │
│ │   ✓ 已选（切换候选可改）    │ │
│ ├────────────────────────┤ │
│ │ [缩略图] 梅花 · 91.0%     │ │
│ │   ✓ 已选（切换候选可改）    │ │
│ ├────────────────────────┤ │
│ │ [缩略图] ❌ 识别失败       │ │
│ │   换一张 / 保存到相册       │ │
│ └────────────────────────┘ │
│  [确认全部入库]  [重新识别失败张] │
└────────────────────────────┘
```

- 每张默认选中第一个命中知识库的候选（与单图一致）；
- 点击某张可展开该张 Top3 候选切换选中（含手动搜索纠正）；
- 失败张显示「换一张 / 保存到相册」，不参与确认入库；
- 「确认全部入库」：逐张调 `saveCard(create)`，返回汇总结果（成功 N 张 / 已收集 N 张 / 失败 M 张）。

## 五、数据与状态设计（前端）

### 5.1 多图数据结构（替代单图 candidates）

```
batchList: [{
  index: 0,            // 批次内序号
  tempPath: string,    // 本地图路径（预览/重识别用）
  fileID: string,      // 已上传云存储（识别成功后保留；失败张清理）
  status: 'ok' | 'fail',
  failMsg: string,     // 失败原因（如识别失败/内容不合规）
  candidates: [Top3],  // 识别成功时的候选（含 species/baike）
  selectedIndex: number, // 该张选中的候选下标
  hit: boolean,        // 是否命中知识库
  meetCount?: number,  // 确认入库后的返回值
  confirmed: boolean,  // 是否已确认入库
  genState: 'none' | 'generating' | 'done' | 'failed' | 'no_quota', // 未收录花生成状态
  speciesId?: string   // 生成完成/已存在时的花种 id
})]
```

### 5.2 phase 状态机扩展

`idle → recognizing → result → success`（单图，保留）
新增：`idle → batch（批量识别中）→ batch_result（清单确认）→ success`
批量确认全部结束后，可逐张进入单张成功动画或统一成功汇总。

## 六、未收录花（新物种）批量识别设计（重点）

### 6.1 现状约束（关键）

- `generateFlowerWorker` **每 2 分钟只处理 1 个** pending 任务（`limit(1)`）；
- 生成配额：每用户**每日 3 次**（`GEN_DAILY_LIMIT`）；
- 单次生成：DeepSeek 科普 + Seedream 插画 + 内容安全 + 入库，约 1~2 分钟。

### 6.2 批量场景的设计策略

1. **清单内独立生成入口**：每张未收录候选（`species: null` 且 `score > 0.4`）在清单中显示「✨ 收录并生成花卡」按钮，各自独立状态（`genState`）；
2. **生成串行**：同一时间只允许 1 个生成任务（沿用 `genIndex` 全局锁思路，扩展为 `batchGenIndex`）——避免多个任务同时轮询混乱；
3. **配额前置提示**：进入生成前检查剩余生成配额（前端可先查 `gen_limits` 或由 `requestFlowerGenerate` 返回 `GEN_LIMITED`）；批量中多个未收录花时，提示「今日生成次数剩余 N 次，超出部分需明日」；
4. **生成任务排队**：未收录花可先确认入库吗？——**不能**，必须等生成完成（未收录花无 species 无法入库）。因此：
   - 批量确认时，未收录候选在生成完成前**不可确认**（置灰 + 提示「正在生成，稍后可确认」）；
   - 生成完成（`attachSpecies`）后该张转为可确认；
   - 批量「确认全部入库」只提交已可确认的；生成中的保留待完成；
5. **长耗时提示**：多张未收录花生成需排队（每 2 分钟 1 个），提示「生成任务按序进行，完成后可回到图鉴查看」；轮询沿用 `pollGenTask`（每 4s，最多 45 次），中途退出后任务仍在后台继续（worker 处理），下次进入图鉴/识别可见。

### 6.3 交互流程（批量含新物种）

```
批量识别完成 → 清单（部分候选未收录）
  │
  ├─ 未收录候选：点「✨ 收录并生成花卡」
  │    ├─ 配额不足 → 提示「今日生成次数已用完」
  │    ├─ alreadyExists → 直接挂花种，转可确认
  │    └─ 建任务成功 → 串行轮询 → done → 挂花种转可确认
  │
  ├─ 已收录候选：直接可确认
  │
  └─ 「确认全部入库」：逐张 saveCard(create)（跳过生成中/失败张）
       → 汇总：成功 X / 已收集 Y / 失败 Z / 生成中 W
```

## 八、边界与风险

| 风险 | 对策 |
|---|---|
| 批量 5 张全未收录 → 生成排队 10 分钟 | 明确提示「按序生成」；生成中张不可确认；完成后图鉴可查；中途退出后台继续 |
| 每日生成配额 3 次不足 | 生成前查剩余配额并提示；`GEN_LIMITED` 错误码引导 |
| 中途退出丢进度 | 已识别结果在前端暂存（本页会话内）；退出只影响未完成张；已入库不受影响 |
| 单张识别耗时叠加 | 逐张进度「3/5」+ 缩略图，避免无反馈 |
| MD5 重复弹窗在批量中打断流程 | 批量中重复图自动跳过（不弹窗），清单标记「重复」并保留已收集花名 |
| 数据量/并发 | 逐张串行天然低并发；确认入库逐张 saveCard |
