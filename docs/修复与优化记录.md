## 批次 2026-08-14：worker 超时链路收紧（watermark 双调用导致 60s 强杀）

**问题**（实测日志 + 任务文档定位）：任务「美人梅」反复被 worker 拾取后卡死在 `generating`——Seedream「带 watermark 失败去参重试」两次串行最坏 80s，加 DeepSeek 20s，必然撞云函数 60s 硬上限被强杀，无错误落盘。

**改动**（`generateFlowerWorker/index.js`）：
- Seedream 改**单次调用**（去掉 watermark 参数与重试，25s 超时）——agentplan 接口本就不需要该参数
- 超时收紧：DeepSeek 20s→15s、图片下载 20s→15s；单任务最坏耗时约 60s 内
- 卡死判定 5 分钟 → **3 分钟**（自愈更快）
- 失败会快速落盘 error（不再悬死），3 次重试后 failed 并退配额，便于诊断

**验证**：`node --check` 通过；重新部署 worker 后：卡死的「美人梅」任务会在 3 分钟内被拾取，成功或快速失败落盘 error。

## 批次 2026-08-13：生成任务卡死自愈修复（generating 悬死重试）

**问题**（真机测试反馈「生成较慢，请稍后在图鉴查看」）：worker 在生成中途被云函数 60s 超时强杀时，任务永远停在 `generating`——而 worker 只捞 `pending`，任务悬死且轮询直到 3 分钟超时。

**改动**：
- `generateFlowerWorker/index.js`：
  - 任务拾取：优先最早 `pending`；其次拾取 **`generating` 且 5 分钟未更新**的卡死任务（续命重试）
  - 新增 `retryCount` 重试机制：失败回到 `pending` 排队重试；**重试满 3 次**才置 `failed` 并退还配额（违规立即 failed 不退；避免重复退款）
  - HTTP 超时收紧：DeepSeek 20s、Seedream 40s、图片下载 20s（尽量单任务在 60s 内完成）
- `requestFlowerGenerate/index.js`：建任务时初始化 `retryCount: 0`
- `recognize.js`：轮询遇 `NOT_FOUND/FORBIDDEN/BAD_PARAM` 立即停止并提示（不再傻等 3 分钟）

**验证**：`node --check` 通过；重新部署两个云函数后：旧卡死任务会在 2 分钟内被自动拾取续命；或控制台手动把该任务 `status` 改回 `pending` 立即触发。

## 批次 2026-08-11：注销保留限流计数（防恶意刷次数）

**问题**（用户反馈）：注销后 `rate_limits` 被删除 → 当日识别计数清零 → 可恶意「注销→重新识别」刷 20 次配额。

**原理**：用户身份由 `cloud.getWXContext().OPENID` 标识，**同一微信号 + 同小程序 = 永远同一 openid**（注销/重进不变），因此保留 `{openid}_{日期}` 计数即可跨注销生效。

**改动**：
- `cloudfunctions/deleteAccount/index.js`：**不再删除 `rate_limits`**；返回体改为 `{ ok, deletedCards, deletedPhotos, deletedHashes, keptRateLimits: true }`；历史计数仍由 `cleanupData` 30 天策略清理
- `pages/profile/profile.js/.wxml/.wxss`：注销第一层确认与最后确认弹窗文案均提示「当日识别次数不会重置（防止恶意刷次数）」；隐私政策第 5 条同步更新

**验证**：`node --check` 通过；重新部署 `deleteAccount` 后测试：用完若干次识别 → 注销 → 重新识别，今日剩余次数与注销前一致。
