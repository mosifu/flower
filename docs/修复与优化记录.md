## 批次 2026-08-19：重复「未识别出植物」照片直接提示未识别出花朵（指纹记录识别状态 nonPlant）

**问题**（用户反馈）：识别时有一张重复照片，点「重新上传」换了张「之前识别为未识别出植物」的照片，结果不是「未识别出植物」而是「重复照片」——因为 `recognizeFlower` 对百度正常返回的照片（无论是否命中知识库）一律写入 MD5 指纹，未识别出植物的照片 speciesId 为空也会被查重拦截。用户希望：**这类照片重复上传时直接提示「未识别出花朵」，而不是「重复照片」**；同时不废弃「识别时写指纹」的方案（避免未识别照片重复调百度浪费次数）。

**改动**：
- `cloudfunctions/recognizeFlower/index.js`：
  - `savePhotoHash` 增加 `nonPlant` 参数，指纹记录新增 `nonPlant` 字段（识别结果留痕：命中花种记 speciesId，未识别出植物记 nonPlant=true）
  - 写入处改为 `savePhotoHash(OPENID, md5, hitSpecies..., !hit)`（`hit = candidates.some(c => c.species)`，与前端非植物判定一致）
  - 查重命中返回新增 `hit.nonPlant`（老数据无该字段时按 `speciesId` 是否为空兜底，无需迁移）及 `remaining/limit`（未识别出植物的重复图前端直接进结果页，配额条需要展示）
- `miniprogram/pages/recognize/recognize.js`：
  - `runRecognize` duplicate 分支：`hit.nonPlant` 时不再弹「重复照片」弹窗——单图直接进「暂未识别出花朵」结果视图（不消耗次数、不重复调百度）；批量重传/重试（`_batchRetryIndex`）场景回填清单该张为 nonPlant
  - `runBatchRecognize` duplicate 分支：`hit.nonPlant` → 标记该项 nonPlant（status=fail、failMsg=暂未识别出花朵）而非 duplicate
- `miniprogram/pages/task-detail/task-detail.js`：`onItemReupload` duplicate 分支先判断 `res.hit.nonPlant` → 用 `updateItemFromResult(idx, { hit:false, candidates:[] }, fileID, false)` 把该项更新为 nonPlant，而非重复标记成 duplicate

**验证**：`node --check` 通过（recognizeFlower / recognize.js / task-detail.js）；`recognizeFlower` 全部 6 个调用点核对——3 处非 force 调用（runRecognize / runBatchRecognize / task-detail onItemReupload）均已处理 nonPlant 分支，3 处 force 调用跳过查重不受影响；文档同步更新（SCHEMA.md photo_hashes 新增 nonPlant、技术文档.md 查重返回/写入指纹/健壮性说明）。

**需用户操作**：重新部署 `recognizeFlower` 云函数 + 前端重新编译。老数据无需迁移（代码按 speciesId 为空兜底判定非植物）。

## 批次 2026-08-17：task-detail.wxss 样式插入错位修复（编译错误 unexpected {）

**问题**（编译报错）：`./pages/task-detail/task-detail.wxss(103:16): unexpected {`——WXSS 编译失败。

**验证**：括号配平深度 0、注释闭合正常；全量扫描 7 个 wxss 文件均无结构问题；重新编译通过。

**经验沉淀**：向已有规则附近插入样式时，锚点必须用**完整规则块**（含花括号），避免插入点落在规则内部破坏结构。

## 批次 2026-08-13：生成任务卡死自愈修复（generating 悬死重试）
